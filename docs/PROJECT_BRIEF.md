# Portfolio project brief

**Snapshot:** 2026-10-23. Validate this against the repository before starting work.

## Purpose
A first-person technical portfolio for Tyler Dalton. Audience: engineering hiring managers, recruiters, peers and collaborators. Emphasis: practical systems, infrastructure, Kubernetes, security, automation, technical decision-making and credible project outcomes. Tone: direct, professional, human and sometimes playful—not corporate boilerplate.

**Production:** https://tylerdalton.dev  
**Source:** https://github.com/tyler-dalton/portfolio  
**Deployment:** Cloudflare Pages per owner's project context; verify current integration/settings in the Cloudflare dashboard or CI before making deployment changes. The repository itself does not establish all production configuration.

## Stack and architectural boundaries
- Astro 7.3.x (package constraint currently ^7.3.3), Tailwind CSS 4, native Astro/HTML/CSS, TypeScript and vanilla browser JavaScript.
- Node >=22.12, npm with checked-in package-lock.json.
- Astro content collections + MDX for projects; sitemap and Markdown/Mermaid support.
- Static site with pre-rendered routes; no server or database in the inspected source.
- Light/dark themes plus an opt-in Matrix easter egg; a site-wide command palette.
- GitHub contribution SVG generated by GitHub Actions, with an accessible img fallback and homepage JS enhancement.

## Navigation and routes
Main structure is defined in `src/data/navigation.ts`:
- **Home**: `/` — headshot, intro, terminal bio, selected work, GitHub contribution graph, command-palette CTA.
- **Work**: `/work`; **Projects** `/work/projects` and filters `/featured`, `/all`, `/infrastructure`, `/development`, `/cybersecurity`, `/misc`; dynamic case studies at `/work/projects/[slug]`; **Resume** `/work/resume`.
- **Activity**: `/activity`, `/activity/github`, `/activity/timeline`, `/activity/changelog`.
- **About**: `/about`, `/about/personal`, `/about/now`.
- **Contact**: `/contact`.
- **Digital business card**: `/card` (no main navigation chrome).

## Relevant existing assets and patterns
- `src/layouts/layout.astro`: default metadata, canonical and social tags, common chrome, theme bootstrap, `theme-color` kept in sync with the active theme, Matrix mounts.
- `src/components/section-hub.astro`: consistent Work/Activity/About hub style.
- `src/components/under-construction.astro`: reusable placeholder; retire from routes as content is completed.
- `src/components/projects/`: cards, project indexes, stats and Panoptes visualizations.
- `src/content.config.ts`: Zod schema for MDX project frontmatter.
- `src/lib/projects.ts`: ordering and filtering, including unique `show.home.order` values 1–3.
- `src/data/resume.ts`: central web-resume content. PDF at `public/media/tyler-dalton-resume.pdf` requires manual synchronization.
- `src/styles/*.css`: CSS custom properties and themed components.
- `src/components/command-palette.astro`: page/theme/Matrix commands. Commands are currently declared manually; any new page needs a discoverability review.
- `.github/workflows/update-contributions.yml`: scheduled graph regeneration. Uses `GITHUB_TOKEN` in Actions; never expose tokens to frontend.

## Project knowledge available for *proposals*, not automatically publishable claims
- **Panoptes**: Summer 2026 Kubernetes observability work (Prometheus/Grafana/Thanos, Helm; RKE2/OpenShift) appears publicly in the existing MDX case study. Retain what is already approved and avoid details of restricted networks, specific security configurations or controlled deployments.
- **Personal infrastructure/homelab**: Proxmox, OPNsense, VLAN design, monitoring, private DNS and automation. Potential strong case study; scope and public-safe topology need explicit review.
- **Kubernetes cluster**: multi-node RKE2, GitOps plans and cluster operations. Distinguish planned versus deployed. A README or GitHub repository is evidence of what it says, not proof of production health.
- **Linux desktop/dotfiles**: configuration, workflow automation and public dotfiles may yield a smaller technical case study.
- **Networking teaching labs/deployment bags**: switch management, security and repeatable lab environments; publish safe, sanitized examples only.

Do **not** automatically publish private IPs, credentials, internal topology, employer-specific details, student information or unapproved internship updates. Professional details such as role, degree and availability must be confirmed by the owner before modifying public copy.

## Success criteria
1. The website communicates specific and truthful engineering contributions within seconds.
2. Navigation and core content are useful on mobile and with the keyboard.
3. Each case study explains problem, constraints, ownership, design decisions, implementation, validation and results.
4. Project listings, activity and career information stay synchronized with credible sources.
5. Maintain a good Lighthouse-style baseline: fast, accessible, low-dependency and resilient.
6. The site remains recognizably Tyler's, with terminal/Matrix flourishes secondary to real work.
